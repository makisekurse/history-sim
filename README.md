# 拟境 · nijing

> 世界书驱动的沉浸式情境推演引擎

把自己放进一个世界，做一个行动，看这个世界如何回应。

不是数值游戏 —— 没有血条、金币和属性面板。全屏是长篇小说的阅读质感，
每一幕由你自己配置的大模型实时生成，结尾给出几个可选行动，也可以直接写下你自己的。

**应用本身不内置任何剧本。** 你演谁、身处什么时代、用什么文风，全部由你写的「世界书」决定。
历史正剧、架空江湖、近未来都市 —— 同一套引擎，换一本书就是另一个世界。

## 它是什么

| | |
|---|---|
| **零 HUD** | 顶栏轻触才出现，3 秒自动淡出。三套纸质主题：时代报章 / 暗夜墨石 / 素雅宣纸 |
| **世界书** | 世界背景、玩家身份与目标、关键人物/势力/地点、世界规则、叙事文风、开场情境 —— 全部可写、可导入、可导出分享 |
| **快速创建** | 一句话描述你想进入的世界，AI 扩写成完整设定。**先预览、可逐项改，确认了才保存** |
| **双模交互** | 每幕给出 2~3 个可选行动，同时保留自由输入框，你可以写任何行动 |
| **世界状态** | 每一幕维护一份结构化的「此刻状态」：时间、地点、已知事实、人物关系、进行中的事件 |
| **世界观察** | 默认收起。想看局势的人点开就能看到当前局面；只想读故事的人永远看不到它 |
| **编年史** | 每 5 幕把前情压缩成摘要回灌上下文，长局不会失忆 |
| **回滚与重来** | 可回滚到任意一幕，可单幕重新生成。回滚会连状态和编年史一起退回，不会留下"幽灵记忆" |
| **拒答兜底** | 模型拒答或输出截断时自动改写重试 → 提示切换通道 → 回落本地降级，游戏不会卡死 |
| **一切只在本机** | 世界书、存档、API Key 都不上传。Key 走系统加密存储 |

## 快速开始

1. 装好 App，首次打开会引导你配置模型接口
2. 设置 → 选服务商（默认阿里云百炼），填 API Key，点「测试连接」
   - 默认模型 `qwen3.8-flash`，便宜、快
3. 「**世界**」标签 → 「创建世界」（快速创建 / 手动编写），或「导入」
4. 「**继续**」标签 → 「开始一段新的推演」→ 选一个世界 → 进入

底部三个入口：**世界**（我创造什么）· **继续**（我正在经历什么）· **我的**（设置）。

### 世界书字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 世界书名 |
| `era` | | 时代与时间跨度 |
| `worldview` | ✅ | 世界观与背景设定 —— 模型据此推演 |
| `playerRole` | ✅ | 你扮演的人物：身份、职务、年龄、性格、立场 |
| `playerGoal` | | 玩家目标：这一局你想做什么 |
| `narrativeStyle` | | 叙事文风 |
| `extraRules` | | 世界规则与禁忌 |
| `keyCharacters` | | 关键人物（一行一条，可空） |
| `keyFactions` | | 关键势力（一行一条，可空） |
| `keyLocations` | | 关键地点（一行一条，可空） |
| `stateDimensions` | | 状态维度模板：告诉模型「当前世界状态」该盯住什么 |
| `openingScene` | | 开篇场景。填了就由你掌控开场，不走模型 |
| `openingChoices` | | 开篇分支（一行一条） |

人物、势力、地点**允许为空** —— 不强迫你为了开始一局填一堆字段。

### 导入 / 导出

在世界列表点「导入」，支持两种输入：

- **JSON**：完整字段。也兼容常见别名（`title`→name、`setting`/`world`→worldview、
  `role`/`character`→playerRole、`style`/`tone`→narrativeStyle、
  `rules`→extraRules、`opening`/`intro`→openingScene、`choices`→openingChoices）
- **纯文本**：整段当作「世界观设定」，其余字段留空待补

长按任意世界书 → 「导出 JSON 到剪贴板」，可直接分享给别人导入。

`worldbooks/` 目录里放了一份示例世界书，复制内容即可导入。

## 世界状态 vs 编年史

这两块都进 system prompt，但职责**严格区分** —— 混了就会互相矛盾：

| | 世界状态 | 编年史 |
|---|---|---|
| 体裁 | 结构化条目 | 散文叙事 |
| 回答 | 此刻是什么状态 | 过去发生过什么 |
| 时态 | 只写当下 | 只用过去时 |
| 体积 | 有硬上限 | 会累积增长 |

判定规则：一条信息，**回滚到第 5 幕后就不成立了** → 归世界状态；
**永远成立** → 归编年史。

模型每幕只在 `<state>` 块里提出状态变化，**合并、校验、截断全部由应用负责** ——
不让模型每幕凭空重写整个世界。上限用总字符预算 + 宽松条数
（事实 ≤12 条、关系 ≤12 条、事件 ≤8 条、单条 ≤120 字），
而不是「每类 5 条 / 每条 40 字」那种硬截断。

## 自己构建

```bash
flutter pub get
flutter build apk --release --target-platform android-arm64
```

> ⚠️ `--target-platform android-arm64` **必须显式指定**。
> Flutter 的 Gradle 插件会绕过 `android` 里的 `ndk.abiFilters`，
> 只用 abiFilters 的话三个 ABI 全都会打进包里（实测 51 MB vs 18.8 MB）。

### CI

GitHub Actions（`.github/workflows/android.yml`）分两级：

| 触发 | 行为 |
|---|---|
| 推 `main` / 手动 | **只构建**，上传 Artifact，**不发版** |
| 推 `v*` 标签 | 构建 + **发布 Release**（这一步才算"发包"） |

需要配置仓库 Secret `TEST_KEYSTORE_BASE64`（固定签名密钥的 base64）。
没配会退回 debug 签名 —— 那样每个包签名不同，无法覆盖安装。

### 图标

`assets/icon/` 下两张 PNG 是图标源文件，改设计后重跑生成脚本再执行
`flutter pub run flutter_launcher_icons` 即可。

## 测试

```bash
flutter test
```

56 项单元测试，覆盖三类最容易出隐蔽 bug 的地方：

- **回滚 / reroll 一致性** —— `history` · `chronicle` · `worldState`
  三者是否始终落在同一个时间点（这类 bug 靠手点界面根本测不出来）
- **世界状态的解析、合并与截断** —— 含畸形输入不抛异常、关系走增量、总预算兜底
- **模型输出解析** —— 10 类畸形标签写法（标签内空格、全角尖括号、中文书名号、
  大小写、未闭合、块在正文前后、多个同名块……）

## 架构

```
lib/
├── core/        常量 · 错误分类
├── models/      世界书 · 幕节点 · 世界状态 · 词条人物 · 存档槽 · 配置
├── data/        本地存储（防抖写）· 加密存储 · 世界书仓库
├── services/    流式客户端 · 输出解析 · 提示词组装 · 拒答兜底
│                世界状态 · 编年史 · 会话状态机 · 存档 · 世界书生成 · 更新检查
└── ui/          主题 · 页面 · 组件
```

依赖自上而下单向流动，下层不反向依赖上层。
**UI 层不包含任何具体剧本信息** —— 界面上出现的每个字都来自当前世界书。

两个关键模块：

- **`services/game_session.dart`** —— 一局推演的状态与纯逻辑
  （history / chronicle / worldState / 回滚 / reroll / 备份），与 UI 完全解耦。
  拆出来是为了让回滚一致性**可以单测**。
- **`services/world_state_service.dart`** —— 世界状态的解析、合并、校验、截断。
  所有写入口都必须过这一道。

### 核心不变量

> `history` · `chronicle` · `worldState` 三者必须永远处于同一个时间点。

实现方式是 `ChapterNode` 上的**每幕快照**（`chronicleAfter` / `worldStateAfter`）。

只在存档顶层存一份「当前状态」是**回滚不到历史幕**的 —— 顶层那份永远是最新的。
回滚、reroll、编年史压缩三条路径都必须维护这个不变量。

### 提示词三层

| 层 | 是否可改 | 作用 |
|---|---|---|
| 内核层 | 锁定 | 输出格式契约（`<date>` / `<choices>` / `<glossary>` / `<cast>` / `<state>`）、角色约束 |
| 框架层 | 可改，可恢复默认 | 叙事框架、创作定位 |
| 世界层 | 完全自由 | 世界观、玩家身份与目标、关键人物势力地点、文风、规则 —— 全部来自世界书 |

### 模型输出契约

模型每幕必须返回带标签的结构，应用解析后渲染。
**这五个块全部是元数据，读者不该看见** —— 只有正文进阅读区：

```
<date>剧中日期</date>
（正文）

<choices>
第一条可选行动
第二条可选行动
</choices>

<glossary>
词条|解释
</glossary>

<cast>
姓名|身份|立场
</cast>

<state>
时间：此刻的剧中时间
地点：主角此刻所在
事实：条目；条目
关系：姓名|此刻态度；姓名|此刻态度
事件：进行中的事件；事件
</state>
```

缺少 `<choices>` 会被判定为截断，走兜底链路。

解析器是四步流水线（标签定位 → 结构块切分 → 结构化提取 → 正文重建），
对畸形输出尽量宽容。**但不做过度正文清洗** ——
正文里出现的 `名字|身份|立场` 行只要不在结构块内就原样保留。
